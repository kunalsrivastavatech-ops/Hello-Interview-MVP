Your job is to turn my existing prototype into a functional MVP step by step.

PRODUCT:
Hello Interview is an AI-powered placement interview simulator for college students, initially focused on B.Tech CSE/core students.

The goal is to simulate the pressure and experience of a real corporate placement interview rather than simply displaying interview questions.

CORE USER FLOW:

1. Candidate opens Hello Interview.
2. Candidate enters/selects:
   - Name
   - Roll number
   - Company
   - Job/assessment track
3. Candidate completes a pre-interview checkpoint.
4. Candidate gives camera and microphone permissions.
5. Candidate starts the interview.
6. An AI interviewer asks interview questions.
7. Candidate answers using their microphone.
8. The application records/transcribes the answer where technically possible.
9. The system evaluates the answer.
10. The interview continues for approximately 5 questions.
11. At the end, show a structured performance report.

MVP PRIORITY:

The MVP must actually work.

Do NOT try to implement every advanced feature immediately.

Build this in phases.

PHASE 1 — JAVASCRIPT FUNCTIONALITY

First connect my existing HTML/CSS UI to JavaScript.

Implement:
- Button interactions
- Navigation between screens
- Candidate setup form
- Company/role selection
- Start Interview button
- Interview question display
- Question progression
- Countdown timer
- Answer submission
- Interview completion
- Final report screen

Use clean, modular JavaScript.

Do not create unnecessary frameworks if they are not needed.

Before changing major parts of the code, inspect the existing project structure.

PHASE 2 — INTERVIEW ENGINE

Create an interview engine that can handle:

- 5 questions per interview
- Different question types
- Question number indicator
- Timer for each question
- Start/stop interview state
- Answer submission
- Moving to the next question
- Final interview state

For the first MVP, use a local question set so the application works even without an AI API.

Example questions for a CSE candidate:

1. Tell me about yourself.
2. Explain one technical project you have worked on.
3. What is the difference between a process and a thread?
4. Explain OOP concepts with an example.
5. Why should we hire you?

Structure the code so that these questions can later be replaced/generated by an AI model.

PHASE 3 — CAMERA AND MICROPHONE

Use browser APIs such as:

to request:
- Camera
- Microphone

Display the camera stream inside the existing interview UI.

Do NOT upload or permanently store video/audio yet.

Handle:
- Permission granted
- Permission denied
- Device unavailable

Gracefully show an error message if camera/microphone access fails.

IMPORTANT:
Do not claim that this provides perfect proctoring or prevents cheating.

PHASE 4 — SPEECH INPUT

Add browser-based speech recognition/transcription where supported.

The candidate should be able to:
- Speak
- See their answer being transcribed
- Submit the answer

If browser speech recognition is unavailable, provide a fallback text-answer input so the MVP still works.

Keep this modular so it can later be replaced with a better speech-to-text API.

PHASE 5 — AI INTERVIEWER

After the basic interview works, integrate an AI model.

Use the Vercel AI SDK if appropriate.

The AI should:
- Generate relevant interview questions
- Adapt questions to company/role
- Evaluate candidate answers
- Generate concise feedback
- Produce a final performance report

IMPORTANT SECURITY RULE:
Never expose an AI provider API key in frontend JavaScript.

Use a server-side/API route for AI requests.

Create a clean interface such as:

generateQuestion(candidateProfile, interviewContext)

evaluateAnswer(question, answer, candidateProfile)

generateReport(interviewData)

Keep AI functionality separated from the UI.

PHASE 6 — SCORING

Create a simple and understandable scoring system.

Initially evaluate:

- Technical relevance
- Answer quality
- Communication clarity
- Completeness
- Confidence indicators based only on observable signals

Do NOT make unsupported claims such as:
"Looking away means the candidate is cheating."

Do NOT treat eye movement as definitive evidence of cheating.

Use cautious wording such as:
"Attention signal detected"

rather than:
"Candidate cheated."

Create an overall score out of 100.

Example:

Technical Knowledge: 78
Communication: 82
Answer Quality: 74
Clarity: 80
Overall Interview Score: 79

The scoring system should be easy to modify later.

PHASE 7 — SILENCE / HINT SYSTEM

Implement a basic silence detector if technically practical.

If the candidate remains silent for approximately 7–10 seconds:
- Show a subtle hint
- Do not immediately mark the answer as wrong
- Allow the candidate to continue

Example:
"Take a moment. Start with the main idea and then explain it."

This should feel like a real interview assistant, not a game.

- Overall score

- Communication
- Answer quality

- Structured responses

- Project explanation
- HR questions
